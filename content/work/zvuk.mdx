После онбординга у <img src="/media/cases/zvuk/sticker-zvuk.svg" alt="" /> Звука есть несколько минут, чтобы доказать: “мы поняли твой вкус”.

<br/>

Я собрал концепт вокруг живых статусов, совместных плейлистов и спокойного прослушивания.
Ожидаемый эффект — рост Retention D7 и вовлечения в первые сессии.

<br/>

  <Media kind="image" src="/media/cases/zvuk/main.png" />
</Gallery>

# Контекст

Пользователь выбирает любимых артистов и ждёт, что следующий экран уже будет про него.

<br/>

Если после этого он видит старые хиты, неточные рекомендации или неочевидный плеер, ценность онбординга пропадает.

<br/>

Нужно было быстрее дать ощущение “Звук понял меня” и добавить повод вернуться в течение недели.

# Почему первый опыт не удерживал

Я провёл аудит, посмотрел конкурентов и протестировал сценарии с 5 пользователями Яндекс Музыки, Apple Music и Spotify.

<br/>

СберПрайм, Hi-Fi или недоступность артистов могут привести пользователя в сервис.
Но привычку они не формируют.

<br/>

В первых сессиях мешали три вещи: неточные рекомендации, прерывания в плеере и слабая социальная динамика.

<br/>

Ценность Звука раскрывалась позже, чем пользователь принимал решение остаться.

# Добавить повод вернуться

Одной персонализации мало.
Рекомендации можно проверить один раз и закрыть приложение.

<br/>

Социальные сигналы обновляются постоянно.
В опросах пользователям как раз не хватало совместных плейлистов, живых статусов и понятного способа слушать музыку вместе.

<br/>

На момент аудита профили уже существовали, но позволяли только посмотреть добавленные треки и альбомы — я предложил развить их в социальный сценарий с живыми статусами и совместной «Силой звука».
Пользователь видит, что слушают друзья, включает треки из статусов и собирает общие плейлисты.

<br/>

<Gallery>
  <Media kind="image" src="/media/cases/zvuk/4_gallery_1.png" />

<br/>

Музыка перестаёт быть только личной лентой.
Она становится поводом для контакта.

Профиль перестаёт быть служебным экраном.
Он показывает музыкальный вкус и сразу даёт действие.

<br/>

В профиле появились:

- живой статус “слушает сейчас”;
- общие плейлисты;
- публичные подборки;
- связь визуального состояния с текущей “Силой звука”;
- шаринг профиля через ссылку или QR.

<br/>

Так профиль становится входом в музыку другого человека.
Можно не только смотреть, но и сразу включать, сохранять или продолжать совместный сценарий.

<br/>

# Защитить само прослушивание

Социальность не сработает, если базовое прослушивание раздражает.
Поэтому плеер остался поддерживающим слоем решения.

<br/>

Я сохранил управление в режиме текста, снизил акцент у действий, которые прерывают музыку, и сделал частые действия доступнее.

<br/>

Смысл не в косметике.
Пользователь должен думать о музыке, а не о поведении интерфейса.

<br/>

# Что не вошло в фокус

Детский сценарий я не смешивал с основным решением.
Для него нужна отдельная логика: безопасность, родительский контроль и ограничения контента.

<br/>

Чаты тоже не стали центральной фичей.
Они уводят продукт в сторону мессенджера.

<br/>

Социальность осталась ближе к музыке: статусы, профили, совместные плейлисты и быстрый запуск треков друзей.

# Результат

Концепт меняет роль первых сессий: пользователь не просто проходит онбординг, а получает ответ от продукта.

<br/>

Сначала Звук показывает, что понял вкус.
Потом даёт повод вернуться через друзей.
Затем удерживает сценарий спокойным прослушиванием.

<br/>

Ожидаемый продуктовый эффект:

- рост Retention D7;
- рост Time Spent в первых сессиях;
- рост вовлечения в персональные подборки;
- рост переходов в профили друзей;
- рост создания и прослушивания совместных плейлистов.

# Вывод

Удержание начинается не с количества функций.
Оно начинается со скорости доказательства ценности.

<br/>

Если пользователь выбрал артистов, продукт должен сразу показать, что этот выбор что-то изменил.

<br/>

Но для возврата через несколько дней одной персонализации мало.

Нужен живой повод.
В этом концепте таким поводом стали люди.
