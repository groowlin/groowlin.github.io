# Games: скрытый игровой режим

## Доступность при сборке

Серверный флаг в `lib/features.ts`: `process.env.ENABLE_GAMES === "true"`. По умолчанию игры отключены; GitHub Pages явно собирается с `ENABLE_GAMES=false`. При отключении `app/page.tsx` не монтирует `GamesExperience` и маскота, исключает все `gameItems` и анонс `mini-games` из списка; `app/layout.tsx` не добавляет игровой bootstrap. MDX и его fail-fast валидация сохраняются: фильтрация выполняется только в сборщике списка страницы. Для локального включения задать `ENABLE_GAMES=true`; смена флага требует пересборки статики. Исходники остаются в репозитории, игровые assets из `public` доступны по прямым URL. Все правила ниже описывают включённый режим.

## Область и компоненты

Таба «Игрушки», disabled spoiler Canvas и tooltip сейчас нет. Главная содержит «Опыт» и «Авторское»; игры открывает независимый маскот `GamesExperience`. Разблокировки таба не существует.

Источник истины для MVP. Режим существует только на `/` и только при ширине viewport от 768px. Он не создаёт route, overlay, modal, drawer, API или backend. При включённом флаге `app/page.tsx` монтирует `GamesExperience` из `components/games/GamesEntry.tsx` сразу после существующего `SiteShell`; список и его page reveal сохранены. Открытый игровой блок занимает место в обычном потоке ниже списка. Маскот `position:absolute` привязан к существующему page main, расположен по центру у физического низа страницы; его размер 125×72 CSS px.

- `GamesExperience`: открытие, закрытие, session restore/persist, desktop gate, прокрутка, маскот.
- `GameModeShell`: последовательность `pixel-perfect` → `characters`, текущая игра, внутренний `onNext` с точками `onGameChange` / `onSequenceComplete`. Финал Pixel Perfect остаётся до нажатия «Далее»; только это нажатие вызывает onComplete → onNext. Серая карточка персонажей появляется поверх финала за300ms, затем onGameChange сохраняет новый currentGameId. Pixel Perfect остаётся смонтированным под входящей карточкой до конца перехода; его backdrop-фильтры не получают новых opacity-обёрток. Восстановление completed само по себе не переключает игру.
- `GameFrame`: стабильная единая игровая карточка без внешнего свечения, обводки и тени, без постоянной шапки или вложенной карточки.
- `PixelPerfect`: стабильные экраны `intro`, `play`, `final-result`; локальные transient-фазы idle/dragging/zooming/measuring/measured/value-exit/success/unzooming/shaking/reset-exit/returning/final-exit, GameArea, камера, измерение и координаты объектов.
- `CharacterPlayground`:6 людей со сбрасываемыми на рынке ролями, 2 AI появляются вместе на задаче4, четыре отдела, зональные speed/quality/budget, шесть задач и три кризиса по5s; gameplay в `ceo-simulator/**`, общий controller и один animation loop.
- `MascotMessage`: стабильный geometry-slot после frame и отдельный центрированный motion-bubble рядом с маскотом, absolute у низа main на Figma offset63px. Slot содержит невидимый финальный двухстрочный sizer, поэтому typing/layout bubble не меняет `messageRef.top` и не двигает frame.

Нет общего заголовка Games, счётчика игр, точек прогресса последовательности или CTA-кнопок. Игровой жест начинается drag самого квадрата.

## Тексты и ассеты

Открытый режим показывает:

- `Отдыхать тоже нужно`
- `Пока начальство не видит..`

Заголовок игры: `Pixel perfect`.

Правила:

- `Передвинь rectangle так` + перенос строки + `чтобы gap был 16 px`
- `Отпускаешь — я замеряю`

Каждое открытие показывает default из `reactions/copy.ts`, без указания количества игр. `PixelPerfect` передаёт валидный gap вместе с outcome; выход за границу передаёт только out-of-bounds. Пересечение площадей создаёт overlap; касание с gap0 — валидный замер.

### Контекстные реплики

- `reactions/types.ts`: общие события, состояние и конфигурационный контракт для разных игр.
- `reactions/copy.ts`: неделимые пары title/body, отдельные shared/campaign/endless группы; новых текстов внутри условий нет.
- `reactions/pixel-perfect.ts`: диапазоны, Campaign-правила, выключенный Endless (`enabled:false`).
- `reactions/engine.ts`: чистые create/react/hydrate/parse; случайный равновероятный выбор среди вариантов без предыдущей пары.
- `pixel-perfect-copy.ts`: тексты и иконки экранов самой игры.

Приоритет: out-of-bounds → gap0 → perfect → special → Endless milestone → Campaign attempt → диапазон ошибки. На действие выбирается одна пара. Campaign получает максимум5 попыток, включая ошибочные отпускания, exact16 завершает досрочно. Пятая реакция не предлагает повторить попытку. До существующего final-result/callback реакция показывается800ms. Переключателя режимов нет; клик в любую точку финальной карточки открывает прототип персонажей. Завершение серии само по себе не переключает игру.

Первая попытка: error1–2 near,3–5 close,6–9 miss,10–15 только «Смело»/«Хм...»,16+ только «Авторское прочтение». Gap0 всегда использует отдельную пару из zero. Perfect на первом ходе выбирает одну из двух пар с равной вероятностью.

Вторая–четвёртая: zero → perfect по общему приоритету; special «Нет! / Верни как было» только при previousError<=2 и currentError>=6. Иначе улучшение/без изменений/ухудшение сравнивают ошибки, а не signed gaps.

Пятая: perfect — «Успеееел, успел»; error1–2 — «Ладно»/«В бэклог»,3–5 — «Засчитаем»,6–9 — «Зафиксировали»,10–15 — «Есть над чем поработать»,16+ — «Согласовано». Gap0 сохраняет приоритет zero.

Out-of-bounds и overlap расходуют по одной попытке и используют общий violationCount для одинаковой последовательности реплик. Только выход увеличивает outOfBoundsCount. Оба пишут null в attempts/history, не добавляют фиктивный gap и не меняют лучший измеренный результат. После пятой попытки открывается финал; если измерений не было, отображается «???».

Endless недоступен в runtime. Сохранены улучшение серии, три одинаковых gap, колебания около цели, потеря близкого результата; milestones5/10/20/30. Seen IDs ограничивают специальные события и milestones одним показом на сессию. Perfect не перебивается milestone. Общий движок использует config.campaign.maxAttempts, а не глобальную константу3.

Аналитика сохраняется в `sessionStorage["portfolio.games.reactions.v1"]`: gameId/mode, currentGap/error, previousGap/error, bestError, attempt, outOfBoundsCount, history, seenMilestones/seenSpecials, lastReplyId. На restore валидируются derived значения и соответствие history основной game session; при несовпадении аналитика восстанавливается из валидных attempts без показа/расходования реплик. Блокировка storage оставляет рабочее состояние в памяти. Перезапуск серии сбрасывает аналитику и seen IDs.

Файлы в `/public/media/games/`:

- `games-default.png`: обычный маскот;
- `games-hover.png`: hover/focus открытия;
- `games-hover-exit.png`: hover/focus закрытия;
- `pixel-perfect.png`: исходная иконка пользователя для intro, отображение109×100 без обработки файла;
- `heart-active.png` и `heart-spent.png`: два пользовательских PNG, контейнеры30×30, без обработки, обе картинки заранее присутствуют в DOM;
- `pixel-perfect-win.png`: иконка обоих финалов109×100; intro использует прибор. Старый heart.svg больше не используется.

PNG используются как 2x-ассеты с отображением 125×72, без обработки изображения. Next Image использует `unoptimized`, eager loading и пустой alt. Все три изображения присутствуют в стабильном SSR markup, чтобы маскот не появлялся с задержкой hydration. На мобильном UI скрыт через CSS; загрузка PNG браузером возможна. При клике фиксируется реально показанный default или hover/focus-вариант. Он не меняется во время ухода вниз; open/close-вариант переключается только после полного скрытия маскота. Кнопка имеет `aria-expanded`, `aria-controls` и имя `Открыть игры` / `Закрыть игры`.

## Состояние и восстановление

Одна запись `sessionStorage["portfolio.games.v1"]`:

```json
{
  "version": 1,
  "isOpen": false,
  "currentGameId": "pixel-perfect",
  "games": {
    "pixel-perfect": {
      "attempts": [],
      "results": null,
      "completed": false
    }
  }
}
```

`attempts` содержит до пяти элементов: signed safe-integer gaps либо null для штрафа в CSS px. После попыток `results` имеет `{ bestGap, deviation }`; `deviation = abs(bestGap - 16)`. При равном отклонении сохраняется более ранняя попытка. `currentGameId` допускает `pixel-perfect` и `characters`. В `games` хранится только прогресс Pixel Perfect: у прототипа персонажей нет попыток или результатов. Старые записи с `pixel-perfect` остаются совместимыми. `completed` вычисляется из exact16 либо исчерпания пяти попыток; точное попадание обязано быть последней попыткой. Валидатор отвергает неизвестную версию/игру, некорректные типы, нецелые значения, попытки после успеха, больше пяти попыток и несовместимые derived results/completed. Старая unlimited-запись с числом попыток больше пяти сбрасывается в чистую закрытую session.

React runtime отдельно хранит восстановленную session-модель и transient state: текущий экран игры, размеры, координаты, pointer capture, движение и lifecycle phase внешней карточки. При начале закрытия ввод блокируется и асинхронная последовательность отменяется, но текущие stage/measurement/позиции остаются на экране до конца shake/fade. Сброс в intro происходит только в returning/closed, когда карточка скрыта; draggable возвращается вправо-вниз24px. При текущей игре Pixel Perfect следующее открытие начинается с intro; выбранная игра `characters` открывается снова с начальными персонажами. При этом persisted `attempts`, `results` и `completed` не очищаются. Если сохранённая игра уже completed, только новый фактический drag из intro начинает новую чистую игровую серию. Координаты и незавершённые жесты не сохраняются. Изменения session-модели сохраняются эффектом; при запрете storage игра продолжает работать до размонтирования, а следующий mount снова закрыт.

`app/games-bootstrap-script.ts` сериализует тот же самодостаточный `parseGamesSession`. При включённом флаге raw inline script в root layout идёт **перед** scroll-restoration script; он безопасно читает запись и задаёт `html[data-games-open]`. Серверное дерево включённого режима всегда одинаково: frame существует, но исходно закрыт и inert. До клиентского восстановления селектор `data-ready=false` использует bootstrap attribute, резервирует раскрытую геометрию и показывает frame сразу для сохранённого open. После восстановления CSS управляется runtime `data-phase`, без закрытого промежуточного кадра. Bootstrap не прокручивает страницу.

Home SPA remount заново читает sessionStorage и синхронизирует html attribute. Reload/restored-open не запускают автоматическую прокрутку; scroll restoration сайта сохраняет своё поведение. Обычная новая независимая вкладка начинает с пустой sessionStorage. Браузер может скопировать sessionStorage при дублировании вкладки или открытии с opener и восстановить её при восстановлении закрытой вкладки/сессии. Это native edge браузера; режим не использует localStorage/cookies/BroadcastChannel для различения такого восстановления и reload.

## Раскрытие и прокрутка

Transient state-machine: открытие `closed → scrolling → opening → open`; закрытие `open → closing → returning → closed`. Фазы не записываются в sessionStorage: `isOpen` сохраняет намерение пользователя, а reload всегда восстанавливает сразу полный `open` либо `closed`.

В `closed` максимальная прокрутка оставляет в viewport нижние 20% списка кейсов. От конца `SiteShell` до физического низа документа остаётся ровно 80svh: существующий flex-gap 60px плюс `GamesExperience` высотой `calc(80svh - var(--rhythm-title-block-top))`. Нижний padding `main` обнуляется только на desktop-странице с маркером `data-games-experience`, а trailing flex-gap после experience компенсируется отрицательным локальным margin. Маскот 125×72px полностью виден, и его нижняя граница совпадает с физическим низом документа и viewport при максимальной прокрутке. Явное открытие выполняется по этапам:

1. `scrolling`: сразу зарезервировать 100svh panel. Вся карточка остаётся inert, невидима и находится ниже viewport. После двух requestAnimationFrame измеряется уже обновлённый layout; страница прокручивается к текущему нижнему пределу документа.
2. В одном callback запускаются smooth scroll, уход маскота и `opening` всей карточки. Frame остаётся `position:absolute` внутри явно позиционированного `.panelContent`; его `top` всегда является panel-local координатой `(messageTop - panelTop - frameHeight) / 2`, поэтому карточка естественно движется вместе с документом при scroll и не остаётся приклеенной к viewport. Карточка начинает движение на80px ниже конечной позиции, выходит из opacity0 и меняет scale с0.92 до1. Framer Motion `animate` ведёт числовой `--games-frame-progress` от текущего значения к1 тяжёлой физической пружиной без заданной duration: stiffness100, damping14, mass1.4, restSpeed0.002, restDelta0.0002. Translate и opacity следуют полному spring-progress, opacity достигает1 на50% пути. Scale использует отдельный monotonic progress: при первом достижении цели фиксируется в1 и больше не участвует в перелёте и обратном хвосте. Rotation и blur отсутствуют. Opening различает `targetReached` — первое обновление progress≥1 — и `settled` — полный `onComplete` пружины. После targetReached и окончания обязательного scroll/ухода исходного маскота close-маскот раскрывается и становится доступен, пока пружинный хвост продолжает settling. Первый bubble остаётся скрытым в фазе `opening` и появляется только после settling вместе с переходом в `open`.
3. Scroll завершается по native `scrollend` либо fallback из четырёх последовательных кадров неизменной позиции **после реального движения**. Уже достигнутая позиция не запускает лишнюю прокрутку; destination ограничен реальным диапазоном документа.
4. После завершения и scroll, и анимаций карточки/маскота перейти в `open`, включить игру и вернуть маскот. Финальная геометрия страницы зарезервирована с первого этапа, поэтому движение карточки не меняет layout.

Закрытие использует отдельный короткий exit до возврата страницы:

1. `closing`: игру сразу выключить, но страницу оставить в открытой scroll-позиции и сохранить panel высотой100svh. Close-маскот уходит одновременно с exit frame: вся внешняя карточка встряхивается400ms, а opacity параллельно с первого кадра уходит в0 за `motion-base`280ms; обе части используют `motion-expressive` (`cubic-bezier(0.22,1,0.36,1)`). Конечный opacity0 фиксируется inline в callback завершения fade до снятия WAAPI effect, поэтому оставшиеся120ms shake не раскрывают базовый opacity1. Обратный progress spring не запускается. Только после завершения обеих параллельных частей и ухода маскота начинается return-scroll; скрытый progress нормализуется в0 для следующего opening.
2. После exit скрытый mascot переключается на default, затем начинается `returning`: smooth scroll идёт к будущему закрытому низу документа, а mascot всё это время остаётся скрытым. Неподвижный anchor заранее поднят на разницу между открытой и будущей закрытой высотой experience: `calc(20svh + 72px + var(--rhythm-title-block-top))`.
3. Только после фактического завершения return-scroll начинается reveal дефолтного маскота. После reveal выполняется переход в `closed`: удаляется резерв100svh и mascot возвращается в bottom0. Целевая позиция scroll заранее учитывает будущую схлопнутую высоту, поэтому удаление panel не меняет итоговую позицию страницы.

Lifecycle отдельно ожидает Promise `targetReached` и `settled` opening spring. Close helper совместно ожидает shake+fade frame и mascot exit; return-scroll создаётся только после этого барьера. Повторный toggle/unmount отменяет цепочку через AbortController: spring controls или WAAPI close-анимация останавливаются, listeners удаляются, ожидание отклоняется `AbortError` без зависания и конкурирующей анимации. Scroll abort по-прежнему удаляет scroll listeners и RAF.

Reload/restored-open сохраняет существующий bootstrap и scroll restoration без изменений: ранний selector при `data-ready=false` сразу задаёт полный panel и карточку в progress1, а hydration восстанавливает session и оставляет `phase=open`. После `readGamesSession().isOpen=true` запускается отдельный локальный `restoreVisual` lifecycle, который не пишет scroll dataset, не вызывает scroll helpers и не меняет `scrollY`. Если `html[data-scroll-restoration]` уже не `pending`, replay начинается сразу; иначе cancellable listener один раз ожидает `window.app:scroll-restored`.

Restore replay блокирует toggle, panel interaction/ARIA, `GameModeShell.active` и close-preview, но не меняет session stats/progress или основной phase. Весь `GamesExperience` fade-ится из текущей opacity в0 за `motion-micro`180ms expressive; inline opacity0 фиксируется до cancel WAAPI, поэтому flash отсутствует. Под opacity0 пересчитывается panel-local frame top, восстанавливается default message, очищаются hover/focus и frame opacity, progress/scale-progress задаются0, mascot скрывается в существующем anchor. Затем commit `restoreVisual=reveal` отделяется одним animation frame и opening spring запускается без scroll. Root opacity0 снимается атомарно только внутри первого spring `onUpdate`, после записи первого progress и scale; reduced/immediate completion использует тот же одноразовый fallback. Поэтому стартовая позиция карточки не может стать видимой раньше spring-owned кадра. Close-mascot раскрывается на `targetReached`, а game включается только после mascot reveal, spring `settled` и независимой задержки message500ms от reveal commit.

Restore использует `interactionRef` AbortController и ref-guard от двойного Strict Mode запуска. Abort удаляет listener/timer, останавливает WAAPI/spring/mascot и нормализует видимый restored-open DOM: root opacity очищена, frame opacity очищена, progress/scale-progress=1, mascot reset/visible, `restoreVisual=null`. Pre-hydration limitation неизбежна: bootstrap-карточка может быть видна до hydration и готовности scroll restoration; replay намеренно начинается только после этих read-only gates.

## Геометрия и попытки

Внутренняя state machine PixelPerfect не меняет размер внешней карточки:

1. `intro`: центрированные иконка109×100, gap `--space-xl`, title42/44 heavy и description20/22 белым, gap12. Текст: `Передвинь rectangle так` + перенос + `чтобы gap был 16 px`; rectangle окрашен градиентом активного квадрата. Draggable справа/снизу24px. На фоне три source-квадрата214px с gap16, левый обрезан границей. Click без drag попытку не записывает.
2. `play`: GameArea занимает всю карточку. Intro и фоновые квадраты уходят crossfade; фиксированная цель120px появляется без morph/перелёта. HUD — пять PNG-сердец30×30 по центру сверху40px, gap `--space-md`; потраченная жизнь меняется на PNG разбитого сердца.
3. `final-result`: оба финала показывают победную иконку и подпись `Лучший результат`. При exact16 заголовок `Пиксель в пиксель`, иначе ближайший к16 gap с `px` или `???`, если измерений нет. Возвращаются фоновые квадраты с progressive blur. Активного квадрата нет. Кнопка на всю карточку с подсказкой `Далее` по клику, Enter или Space открывает `characters`: `reset-exit` начинает прежнюю встряску, на следующем animation frame серая карточка с персонажами монтируется поверх финала и появляется из opacity0 за300ms. Финал остаётся под ней до конца перехода, поэтому прозрачного промежутка нет. Progressive blur сохраняет свою структуру и статичные фильтры. После появления второй карточки Pixel Perfect размонтируется, а currentGameId сохраняется без очистки результата. Повторное нажатие во время перехода заблокировано.

Только один квадрат является button и перемещается в двух измерениях; второй квадрат — неподвижная цель. Оба120×120, radius16; target #363636, draggable gradient #D3D9FF→#7E91F6 сверху вниз, без тени и индивидуального scale. Hover draggable добавляет центрированную обводку2px #0C8CE9 (1px внутри,1px снаружи); при drag, во время показа измерения и во время анимации ошибки она отсутствует. Координаты относятся к GameArea. Pointer Events дают primary pointer capture, поэтому pointerup обрабатывается и за пределами карточки. Порог движения4px; click попытку не записывает. Новый pointer/keyboard input доступен во всех transient-фазах открытой игры, кроме фаз показа измерения `zooming`, `measuring`, `measured`, `value-exit`, `unzooming` и фаз ошибки `shaking`, `returning`, когда hover, drag и клавиатурное перемещение заблокированы. В остальных transient-фазах новый ввод инвалидирует текущую async sequence, очищает measurement и продолжает взаимодействие из согласованного play-state без отложенных обновлений отменённой попытки. Pointer-drag не обрезается bounds. Для конкретной точки захвата вычисляется прямоугольник координат курсора, в котором объект полностью находится внутри GameArea. Внутри него позиция объекта следует за курсором1:1. После выхода используется нормализованное экспоненциальное влияние `w(u) = (exp(-3u) - exp(-3)) / (1 - exp(-3))`, где `u` — положение курсора между границей свободной области и соответствующим краем viewport. Влияние непрерывно равно1 у карточки, быстро падает в начале и медленно доходит до0 на границе viewport. Позиция объекта вычисляется аналитическим интегралом этой функции: `F(u) = ((1 - exp(-3u)) / 3 - u × exp(-3)) / (1 - exp(-3))`; отображение по оси равно `boundary ± span × F(u)`. Расчёт каждый кадр идёт из полного смещения от начала drag, а не накапливается, поэтому обратное движение проходит точно ту же кривую и внутри карточки точка захвата снова совпадает с курсором. Диагональ использует одновременно независимые viewport-relative преобразования X/Y. Координаты округляются до целого CSS px. Клавиатурное перемещение, initial/resize и cancel остаются ограниченными area за вычетом120px; это не позволяет увести keyboard-focus объект за доступную область.

Mouse/pen использует grab/grabbing и `touch-action:none`. Клавиатура: стрелки1px, Shift+стрелки10px, Enter/Space запускает замер после движения, Escape отменяет. Инструкции доступны скринридеру; закрытый frame inert.

На отпускании после движения сначала проверяется полное попадание draggable в GameArea: `x >= 0`, `y >= 0`, `x + 120 <= width`, `y + 120 <= height`. Если хотя бы часть объекта снаружи, этот исход имеет приоритет над возможным overlap: measurement не создаётся, записывается штрафная попытка(null), сразу эмитится `out-of-bounds`, карточка встряхивается0–150ms, затем draggable возвращается вправо-вниз24px за150–300ms.

Для полностью находящегося внутри объекта:

1. Вычислить overlap проекций по X и Y как `max(0, min(end) - max(start))`.
2. Больше overlap по Y → горизонтальный gap. Больше overlap по X → вертикальный gap.
3. При точном равенстве выбрать доминирующую ось последнего ненулевого движения pointer; при одинаковых абсолютных компонентах детерминированно выбрать X.
4. Отсортировать объекты по выбранной координате и вычесть дальнюю грань первого из ближней грани второго. Разделение положительное, касание 0, проникновение отрицательное; полностью совпавшие 120×120 объекты дают -120.
5. Сохранить полный `Measurement` (`axis`, signed `gap`, `start`, `end`) и заблокировать ввод на время локальной последовательности.

После обычного release zoom и рисование измерительной линии начинаются одновременно и занимают400ms; в400–1000ms число результата показывается600ms. Число входит через opacity/blur80ms и выходит за последние80ms из600ms. SVG-сетка имеет шаг1 в исходных координатах и масштабируется вместе с объектами: gap N содержит N клеток. При несовпадении ортогональных проекций пунктирные перпендикуляры4/4 соединяют размерную линию с физическими краями объектов. Затем обычный miss возвращает камеру и draggable по прежней логике; пятое измерение или exact16 переводит в final-result. Shake применяется для пересечения площадей объектов и выхода за bounds; эти действия расходуют жизнь.

При пересечении площадей либо выходе за bounds измерение не показывается: записывается штрафная попытка(null), карточка встряхивается150ms, квадрат возвращается150ms. При исчерпании лимита после общей800ms реакции открывается нейтральный финал. Gap0 без пересечения остаётся измеряемой попыткой.

Чтобы квадрат оставался видимым снаружи, clipping `.frameSurface`, `.gameScreen` и `.area` временно переключается в `overflow:visible` для transient-фаз `dragging`, `shaking`, `reset-exit` и `returning` в play. В `idle`, zoom/measurement и unzoom сохраняется `overflow:hidden`, поэтому масштабируемая сцена не выходит за скруглённые границы карточки. Очень далёкий pointer-drag потенциально может увеличить scrollable overflow страницы; отдельный portal/fixed drag-layer пока не используется.

Camera scale зависит от фактических координат ближайших граней. Для выбранной оси: `faceSpan = abs(axisEnd - axisStart)`, `availableSpan = axisSize - 240`, `scale = availableSpan / max(faceSpan, 1)`. Translation по оси равен `120 - min(axisStart, axisEnd) × scale`; по ортогональной оси измерительная линия центрируется в GameArea. Поэтому после zoom две измеряемые грани находятся ровно в120px от противоположных краёв при любом ненулевом расстоянии. `max(faceSpan, 1)` — только защита вырожденного gap0, в котором одну совпавшую координату математически невозможно одновременно отобразить в две разные точки. Линия, endcaps и value вынесены из масштабируемой сцены в screen-space overlay: линия/endcaps имеют постоянную толщину1px и оранжевый цвет #ff835e; число regular белым на оранжевой плашке #ff835e. При вертикальном замере плашка находится справа от линии, при горизонтальном — снизу по центру.

## Конструкция Dialed и дизайн-система

Карточка — единый широкий shell. `GameFrame` содержит только внешнюю поверхность; `PixelPerfect` держит одну постоянную GameArea, а `CharacterPlayground` — отдельное SVG-поле в той же поверхности. Постоянного `GameHeader`, вложенного screen shell, кнопок, nav/progress/list/route нет.

Карточка: radius `--home-top-card-radius`, фон #111111, белый основной текст. Белая обводка, внешняя тень и свечение удалены. Точечной сетки нет; measurement использует прежнюю SVG-сетку. Цвет hover-обводки квадрата #0C8CE9. Линия, пунктир, засечки и обводка значения оранжевые #ff835e; число белое, вся плашка залита оранжевым #ff835e.

GameArea `position:absolute; inset:0` задаёт bounds всей внутренней площадью. Intro/final-copy центрирован с нижней компенсацией `--space-xl`. Два фоновых квадрата214px разделены16px. Общий DS-компонент `ProgressiveBlur` усиливает размытие слева направо через пять перекрывающихся backdrop-filter слоёв0/5/10/20/40px с индивидуальными mask-image и webkit-префиксами. Он возвращает Fragment из span без DOM-обёртки; направление и слои параметризуются. Игровые радиусы и пары масок0/25,8/35,16/45,24/55,32/65% остаются локальной конфигурацией `PixelPerfect`, не DS defaults или tokens. Сами слои — обычные span с постоянной opacity1, без Motion/WAAPI, transition и will-change. Они постоянно смонтированы после получения bounds; crossfade меняет квадраты позади них. Порядок: квадраты z0, blur z1–5, tint z6, всё внутри отдельного фонового контейнера. У слоёв нет общего opacity/filter-контейнера, отсекающего фон от backdrop. Отдельный градиент #111111 достигает100% справа. Фоновые квадраты и blur расположены в общем контейнере, который всегда обрезает содержимое по радиусу карточки, включая уходящие слои при старте drag. Foreground расположен выше слоёв; сердечки выше активного квадрата. Иконка и декор не перехватывают drag.

Текущий progressive blur Pixel Perfect подтверждён пользователем. Каноническое правило: [Progressive Blur](../../design-system-spec.md#progressive-blur). В CSS обязательно сначала `-webkit-backdrop-filter: blur(var(--progressive-blur));`, затем `backdrop-filter: blur(var(--progressive-blur));` с одинаковым значением.

MascotMessage копирует поверхность preview интерактивного содержания: padding `--space-lg --space-xl`, border1 `--surface-glass-border`, radius `--home-bubble-radius`, background `--white-20`, backdrop blur8px и тот же набор inset/outer shadows. Размеры шрифта не меняются; gap title/body уменьшен до `--space-xs`.

### Размеры и responsive lifecycle

На desktop карточка имеет заданную ширину `min(672px, доступная ширина между существующими page gutters)` и высоту50svh. Открытый panel имеет высоту100svh. Вертикальная позиция вычисляется по реальной геометрии `MascotMessage`: центр карточки находится на середине отрезка между верхом viewport и верхней границей bubble. `ResizeObserver` и viewport `resize` обновляют CSS custom property `--games-frame-top`; document scroll не пересчитывает значение, потому что panel и bubble движутся вместе. Фиксированный margin для позиции не используется.

`--games-frame-width: min(672px, 100vw - 2 × layout-padding)`

`--games-frame-height: 50svh`

Открытый experience состоит из 72px маскот-резерва и panel 100svh. При прокрутке к низу panel ровно занимает viewport, а список кейсов находится выше viewport. Закрытый panel остаётся `height:0`, `overflow:clip` с `display:none` для frame. Восстановленный до hydration open использует ту же открытую геометрию. GameArea не скроллится: ResizeObserver пересчитывает draggable bounds по фактической внутренней высоте50svh. Базовые грани объектов остаются120×120 CSS px; zoom применяется общей камерой только во время демонстрации измерения. Мобильный режим по-прежнему отсутствует.

В восстановленном незавершённом play target и draggable начинают с центрированной композиции gap53 и вертикальной разницей20. Intro draggable стоит справа/снизу24px; final его не содержит. Первый mount происходит после расчёта bounds без анимации координат. Перетаскивание следует за указателем непосредственно. Смена состояния цели использует параллельный crossfade280ms с экранным blur16px без tween позиции или размера. После обычной попытки активный квадрат возвращается прежней пружиной550ms, bounce0.16; crossfade других переходов параллельный280ms с экранным blur16px. Камера анимируется только для измерения. На последнем замере/победе камера остаётся в zoom, оба квадрата исчезают через opacity и blur280ms без zoom-out; финальный текст и фон появляются одновременно с уходом игрового слоя.

### Reduced motion

Reduced motion отключает zoom/unzoom, shake и анимационный blur, сохраняет логический порядок и статический progressive backdrop blur intro/final; обычные stage crossfade переходят мгновенно (duration0). Переход к следующей игре сохраняет одновременный уходящий и входящий opacity-crossfade по300ms без shake. Внешний lifecycle карточки и возврата страницы остаётся прежним. Визуальную проверку выполняет пользователь.
## Вторая игра: симулятор руководителя

Текущая итерация развивает существующий MVP поверх прежних SVG-персонажей, spring/rigid constraints, scripted launch, recovery и общего animation loop. Игровых движков и новых runtime-зависимостей нет. Карточка, типографика и переход из Pixel Perfect сохраняются.

### Конфигурация и состояние

В `ceo-simulator/config.ts` находятся роли, зоны, прямые вклады сотрудников, zonal thresholds, шесть задач, три кризиса, transition timings, AI kick, trail, landing effect, contextual hints и общий `GAME_CONFIG`. Числовой баланс и тайминги доступны через временный runtime tuning. Параметры исходной физики остаются в `CHARACTER_CONFIG`.

Типы ролей и зон: ANALYTICS, DESIGN, DEVELOPMENT, QA. У человека роль может быть null; у AI профессии нет. Назначение, возвращение на рынок и физическое состояние хранятся отдельно. Controller хранит worldPosition, height и существующую артикулированную позу. У каждого AI собственный pushCycle. Состояния игры: NORMAL_TASK → FINAL_PHASE → FINISHED.

### Геометрия и рынок труда

Четыре отдела стоят в одной горизонтальной строке: Аналитика, Дизайн, Разработка, Тестирование. Мировые прямоугольники рисуются параллелограммами с горизонтальными передней и задней границами. Проекция: screenX = originX + (worldX + worldDepth × 0.4) × scaleX; screenY = originY − worldDepth × scaleY. `scaleX` зависит только от доступной ширины карточки, поэтому при уменьшении высоты сохраняются экранная ширина отделов и горизонтальные промежутки. `scaleY` равен меньшему из `scaleX × 0.55` и вертикального масштаба, доступного до задней границы пола: низкая карточка сжимает только глубину отделов. Глубина уходит вверх и вправо. Персонажи остаются вертикальными относительно экрана.

Отделы расширены по ширине карточки, разделены более широкими промежутками и приближены к квадратным пропорциям. Геометрия задаётся локально в конфигурации игры, без новых глобальных токенов.

Текущие мировые прямоугольники: x=−160/140/440/740, y=550, ширина240, глубина400; промежуток60. Общая задняя граница — depth950. Проекция вписывает размах отделов, включая наклон глубины, в доступную ширину карточки; при дефиците высоты задняя граница остаётся внутри доступной вертикальной области за счёт независимого `scaleY`.

Рынок труда — всё доступное пространство вне отделов. Отдельная FREE_AREA ниже отделов сохраняет прежние границы случайной ходьбы безработных; она не ограничивает область увольнения или приземления. Назначенные сотрудники гуляют внутри своего отдела. Персонаж вне своей области ходьбы постепенно возвращается в неё.

Наземное перемещение и приземление ограничены физическими границами карточки и общей задней линией отделов: выше неё нет доступного пола. Перенос и полёт могут проходить выше этой линии за счёт высоты, без ухода дальше в глубину. Во время grab голова остаётся внутри скруглённой границы карточки; после release баллистический полёт может пересечь верхнюю границу. Resize меняет проекцию с сохранением мировых позиций. Depth sorting использует projected ground position; переносимые персонажи идут поверх наземных. Простые овальные тени привязаны к ground anchor и немного растут с высотой.

### Grab, carry и throw

Hit area 44×44px остаётся около головы; hover не меняет позу. PointerDown фиксирует pointer и смещение точки захвата относительно головы. Привязка к курсору действует с первого пикселя движения, в том числе на высоте0–40px, без скачка при переходе к переносу. Захват доступен и назначенным сотрудникам; отмена pointer очищает удержание. При `blur` и скрытии вкладки runtime отменяет grab у всех персонажей, включая захваты без записи в локальной pointer-map, очищает историю samples и не переносит скорость жеста в бросок.

Перемещение по полу и высота разделены. При диагональном подъёме доля движения в глубину интерполируется0.70–0.95 в зависимости от доли горизонтального жеста. После упора пола в заднюю границу дальнейшее движение вверх целиком становится дополнительной высотой. Высота больше не фиксирована на40px. Захват в полёте сохраняет текущую экранную позицию.

Release использует недавнюю историю pointer samples. Вертикальный жест даёт более сильный импульс высоты, чем горизонтальный — импульс перемещения по полу. Высота рассчитывается баллистически: z(t)=z₀+v_z×t−gravity×t²/2; длительность определяется достижением пола. Приземление использует фактическую наземную позицию в разрешённых границах. Исходные длины сегментов, springs и recovery сохранены. Новых частей тела нет.

Локальные параметры управления: история указателя80ms; горизонтальный импульс×0.3, вверх×0.45, импульс глубины×0.1; ограничение скорости1500px/s; gravity1400px/s². AI scripted launch сохраняет отдельный vertical impulse380 и не зависит от коэффициента ручного броска. Значения задаются в `GAME_CONFIG`.

Основа расчёта — независимость горизонтальной и вертикальной составляющих [баллистического движения](https://openstax.org/books/university-physics-volume-1/pages/4-3-projectile-motion), ограниченный шаг симуляции по [Fix Your Timestep](https://gafferongames.com/post/fix_your_timestep/) и [pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture) на стабильном элементе поля. Соотношение вертикального и горизонтального импульсов — локальная настройка управления игрой, а не физическая константа; ощущение броска оценивает пользователь.

### Роли и назначение

Старт —6 нейтральных людей на рынке, без AI. Два AI одновременно и однократно появляются на рынке при показе задачи4; больше двух AI не создаётся. Человек при попадании в отдел получает его роль независимо от предыдущей профессии. Подъём отключает активное назначение; во время полёта и recovery вклад отсутствует.

Прямой перенос между любыми отделами разрешён людям и AI. Возвращаться на рынок перед сменой роли не нужно. Вне отделов назначение снимается, человек становится безработным; случайная ходьба по-прежнему ограничена исходной FREE_AREA.

Все люди сохраняют нейтральные контуры независимо от роли. Белая внутренняя заливка, глаза и исходный вид AI сохраняются. Подсветки зон, adjacency, частичной эффективности, hover-позы и native title tooltips нет.

### Метрики и задания

Верхней task-card, номера задания и текстового списка criteria нет. Компактный HUD высотой60–80px содержит по одной цельной шкале Speed/Quality/Budget и встроенный countdown кризиса. Каждая шкала без белой подложки, чёрной рамки, gaps и button-like сегментов: три seamless-зоны используют пастельные low `#d58b8c`, normal `#e2c66f`, high `#87b895`, а текущее значение передаётся непрерывной шириной fill. Width и цвет fill переходят за300ms. Acceptable-зоны мягко пульсируют; minimum Normal подсвечивает Normal+High. Стрелок и постоянных checks внутри шкал нет: false→true даёт один success-pulse350ms и возвращается в спокойное состояние. Точные thresholds в gameplay не показываются. До предоставления финальных metric-иконок используются нейтральные slots фиксированного размера.

### AI и обратная связь

Каждый активный AI имеет независимый цикл: первое ожидание1.9–3.9s, базовый интервал6s. Удар использует исходные части тела: замах220ms, удар100ms, возврат180ms. Реальный push начинается в фазе удара и направлен в область ходьбы рынка. Длительность зависит от расстояния; вертикальный импульс согласован с длительностью и общей гравитацией, поэтому увеличение расстояния не сжимает весь полёт в прежние0.32s.

Один человек резервируется только одним AI. Grab отменяет подготовку или резерв цели; AI, airborne и recovering нельзя выбрать целью. Неактивный AI не отсчитывает цикл, новое назначение запускает новое первое ожидание. Выбитый человек после приземления на рынке становится нейтральным.

Постоянных подписей AI под отделами нет. Zone-specific requirement появляется fade/scale только у требуемого текущей задачей отдела; задача на количество использует один компактный счётчик в HUD и marker только там, где AI уже размещён. У каждого AI есть локальный icon-slot: без активного человека в том же отделе он серый/inactive, с человеком плавно проявляется и получает мягкий glow. До предоставления финальной иконки слот остаётся нейтральной заглушкой; normal и held SVG-копии используют одинаковое состояние и геометрию.

Ручной бросок и AI push используют общий lifecycle: startFlightEffects → updateTrail → finishTrail → spawnLandingEffect. След строится по реальным экранным позициям персонажа в canvas под слоем персонажей: до12 точек за200ms, исчезновение120ms, минимальная скорость100px/s, opacity0.12 и stroke3.2px. Цвет линий берётся из существующего токена gray-700; финальная точка полёта записывается перед fade. Прозрачность уменьшается по возрасту точек. При ходьбе, recovery и обычном переносе след не появляется. Landing effect остаётся в отдельном canvas над персонажами: две симметричные линии длиной16px начинаются на20px левее и правее центра приземления, сохраняя gap40px, и расходятся вверх-влево и вверх-вправо под45°,120ms, opacity0.4 и stroke1.6px; облаков и частиц нет. При ощутимом падении восстановлена тряска всего GameFrame длительностью180ms через Web Animations API; reduced motion её отключает.

Внизу показывается компактный sketch bubble с неровным контуром, без хвоста и белой подложки. Варианты normal/think/robot/shout/whisper и красные markers !/!!/!!! задают семантику без тяжёлого UI. Reveal/hide использует opacity и scale `.96↔1` за220ms; при смене текста старое сообщение сначала полностью fades out, затем новое fades in. При старте задачи bubble кратко показывает её сценарную фразу; при взаимодействии исчезает. После idle-delay тот же bubble показывает одну приоритетную hint. Триггеры: все свободны, нет разработки, низкий бюджет, неэффективный AI, низкое качество, отсутствуют аналитика/дизайн/QA, долго не возвращены выбитые сотрудники.

### Финальная фаза и отчёт

После задачи6 идут три кризиса: «Сократите расходы» (budget High, speed Normal+), «Клиенты недовольны» (quality High, budget Normal+) и «Релиз сегодня» (speed High, budget High). Countdown5s запускается сразу в playable HUD; его видимость меняется fade-переходом. Success требует hold0.7s. Каждый кризис завершается success или fail, показывает result500ms через последовательный bubble crossfade и всегда переводит к следующему.

Главный verdict отчёта определяется числом успешных кризисов:3 — «Компания растёт»,2 — «Бизнес удержался»,0–1 — «Компания обанкротилась». Blocking failure state нет. Дополнительные средние метрики и income сохраняются. Отчёт и restart-control не используют белые подложки и появляются fade-переходом. В FINISHED симуляция и rAF останавливаются.

«НАЧАТЬ ЗАНОВО» создаёт новую CeoGame:6 role=null людей, ноль AI/назначений/прогресса/таймеров/статистики/отчёта и очищенные hints/effects. Закрытие сохраняет reset-on-reopen lifecycle; скрытая вкладка приостанавливает время и физику.

### Временная панель настройки

Техническая панель управляет per-instance runtime-конфигом без persistence: физикой, тенью, AI kick, trail/landing, порогами Normal/High для всех трёх метрик, стоимостью сущностей, AI boost и hold/timer timings. Evaluator читает runtime thresholds; числа не попадают в gameplay UI.

Поля ограничены безопасными min/max/step. Пары глубины grab и первого ожидания AI нормализуются с инвариантом min≤max, а pointHistory — целое число не меньше2. «Перезапустить игру» создаёт новую CeoGame с текущими runtime-значениями. «Сбросить параметры» создаёт независимую копию исходных значений и перезапускает игру. Перезагрузка страницы также возвращает исходные значения. Панель временная и должна быть удалена после фиксации финальной калибровки в config.ts.

### Производительность и границы итерации

Один rAF и bounded physics substeps1/120s сохранены. Физика/AI работают вне React state; SVG-персонажи, два canvas эффектов и UI обновляются через refs, DOM layout измеряется только при input/resize. Trail и landing используют отдельные canvas-слои без DOM-узлов на каждую точку следа: trail находится под персонажами, landing — над ними. Удерживаемый персонаж зеркалится в отдельный pointer-transparent SVG overlay выше header/metrics; его исходный экземпляр в поле на время grab скрыт.

Мебель, окружение, новые персонажи, увольнения и банкротство не добавлены. Endless mode с текучкой/выгоранием/событиями/кризисами остаётся только будущим направлением без игровой логики и кнопок.

## Хореография маскота

State-machine окна и session schema сохранены. Transient motion реализован отдельно в `mascot-motion.ts` через Web Animations API с DS motion-base280 и expressive easing `cubic-bezier(0.22,1,0.36,1)`.

- Перед резервированием 100svh panel кнопка фиксируется в текущих экранных координатах: изменение геометрии страницы не сдвигает видимый маскот.
- Opening: уход вниз начинается в том же callback, что и первый smooth scroll и вход всей карточки. Конечный translateY выводит верх кнопки за нижнюю границу viewport; после ухода она скрыта до phase=open и возвращается снизу в свой обычный page-bottom anchor.
- Closing: текущий close-маскот уходит одновременно с shake→fade внешней карточки, пока scroll остаётся неподвижным. Только после обоих exit скрытый asset переключается на default; return-scroll проходит при полностью скрытом маскоте, и его возврат снизу начинается лишь после полного завершения scroll, до схлопывания panel.
- Неподвижный `entryAnchor` имеет прежние 125×72px и положение у нижнего края страницы. Returning bottom compensation перенесён на anchor, поэтому scroll измеряет layout без transform кнопки; удаление резерва не сдвигает конечную позицию. Anchor не имеет transform и обрезает обычный нижний въезд кнопки, не увеличивая scrollHeight.
- На время ухода кнопка использует transient fixed-позицию; после скрытия восстанавливается обычная геометрия. Перед началом фиксируется реально показанный default либо hover/focus-ассет. Целевой open/close hover-ассет применяется, пока opacity кнопки равна0, и только затем снимается фиксация. Новый toggle отменяет старую анимацию и сохраняет её текущую экранную точку перед перенаправлением. Переход на mobile сбрасывает transient стили.
- Возврат занимает те же280ms; reduced motion использует duration0. Reload с сохранённым open не запускает choreography. Bubble активируется непосредственно при клике открытия вместе с переходом в `scrolling`; его собственная фиксированная задержка500ms не зависит от progress, targetReached или settling карточки.

### Сообщения маскота

Stable `.message` slot центрируется собственным `translateX(-50%)`; внутренний `.messageBubblePositioner` — полноширинный grid с одной общей центрированной area, поэтому Framer Motion `y` не перезаписывает горизонтальное центрирование. Каждая полная реплика рендерится отдельным bubble со своим конечным статичным intrinsic/hug размером. Outgoing и incoming bubbles накладываются в одной grid-area и не анимируют width/height. Невидимый sizer с title и двухстрочным body удерживает постоянную высоту slot и стабильный top для расчёта внешней карточки.

- Fresh enter bubble: через фиксированные500ms после клика `Открыть` opacity0→1, blur6→0 и y12→0 за `motion-base`280ms с `motion-expressive`. Отсчёт запускается фазой `scrolling` и не связан с анимацией карточки. Задержка относится только к первому reveal после активации; смены сообщений и exit её не используют.
- При новом message id AnimatePresence `mode=sync` одновременно выводит старый полный bubble opacity1→0/blur0→4 и вводит новый полный bubble opacity0→1/blur4→0 за `motion-micro`180ms с `motion-expressive`. Dots, typing, задержки, timer-generation и layout-size animation отсутствуют.
- Hover и focus close-маскота объединяются через OR только при `mascotOpen && phase=open`. Override `Закрыть` / `Ладно, пора за работу..` входит и выходит тем же полным bubble crossfade180ms. Pointer hover отслеживается отдельно; pointer-down сбрасывает keyboard flag, а focus включает его только при фактическом `:focus-visible`. Поэтому обычный mouse-focus после pointer-leave не удерживает close-copy. `blur` всегда сбрасывает keyboard flag. Counters не меняются.
- Visual text имеет `aria-hidden`; отдельный atomic polite sr-only status получает полную normal-copy сразу. Hover-only override в live region не попадает.
- Reduced motion убирает y и blur, но сохраняет opacity crossfade180ms между полными bubbles.

Хореография маскота синхронизирована с единым frame lifecycle по общей модели окна Dialed. Lifecycle-тесты покрывают одновременный старт со scroll, фиксацию до reserve, уход/возврат, abort и reduced motion.


Тесты движка: `node --test tests/games/reactions.test.mjs` покрывают диапазоны, уточнённые приоритеты, OOB, terminal copy, seen events, выключенный Endless и сохранение аналитики.
