# Case MDX Blocks Reference

Кейс теперь хранится в MDX, а не в JSON `sections[]`.

## Поддерживаемые MDX-компоненты

### 1) `Media`
Props:
- `kind?: "image" | "video" | "gif"` (default: `image`)
- `src?: string`
- `aspectRatio?: string`
- `caption?: string`
- `placeholderToken?: string`
- `openable?: boolean` (default: `true`, используется только для media внутри `Gallery`)

Пример:
```mdx
<Media kind="image" aspectRatio="16 / 9" src="/media/hero.png" />
```

Поведение layout:
- Соотношение сторон сохраняется по загруженному файлу (или по `aspectRatio`, если задан).
- Для контента кейса media растягивается по ширине контейнера.
- Media выходит за границы текстового контейнера на `20px` слева и справа.
- Скругление media — `20px`.
- При загрузке media допускается только короткое системное состояние `blur + opacity + scale` из `MediaPlaceholder`; отдельные кастомные анимации на уровне MDX-контента не поддерживаются.

### 2) `Gallery`
Использование:
- Используется как MDX-компонент: `<Gallery> ... </Gallery>`.
- Внутри `Gallery` поддерживаются только `<Media />`.
- Количество media не ограничено.
- Media внутри `Gallery` открывается во fullscreen-overlay по клику или тапу.
- У конкретного `<Media />` внутри `Gallery` fullscreen можно отключить через `openable={false}`.
- Это поведение относится только к media внутри `Gallery` и не применяется к preview, avatar, SVG-иконкам и другим изображениям вне `Gallery`.

Правила раскладки:
- Desktop/tablet: максимум `3` media в строке.
- Для `n <= 3` — одна строка из `n`.
- Для `n > 3` — строки только по `2` или `3` элемента, распределение сбалансированное.
- Алгоритм: `rows = ceil(n / 3)`, стартуем с `rows` строк по `2`, остаток распределяется по `+1` в последние строки.
- Примеры: `4 => 2+2`, `5 => 2+3`, `6 => 3+3`, `7 => 2+2+3`, `8 => 2+3+3`.
- Mobile: максимум `2` media в строке.

Отступы/форма:
- Gap между media и между строками — `20px`.
- Весь блок `Gallery` выходит за границы текстового контейнера на `20px` с обеих сторон.
- Fullscreen-overlay закрывается по `Escape`.
- На устройствах с fine pointer fullscreen-overlay закрывается кликом в любой точке overlay; системный курсор остается обычным, а отдельный close-индикатор следует за курсором, в том числе над media.
- На touch/coarse pointer используется обычная fixed close-button в правом верхнем углу.
- Fullscreen media сохраняет свой тип (`image`/`video`) и вписывается в viewport с `contain`.
- Горизонтальный размер fullscreen media ограничен правилом `min(viewport, page container + 640px)`.
- Backdrop fullscreen-overlay использует `var(--white-20)` и `blur(20px)`.
- Open/close motion fullscreen-overlay задаётся самим UI-рендерером:
  - открытие и закрытие происходят через переход между source bounds media и modal bounds;
  - backdrop появляется/исчезает через короткий fade + blur;
  - на fine pointer floating close-indicator следует за курсором;
  - на reduced motion все эти переходы схлопываются в мгновенное состояние без анимации.
- Hover-отклик trigger внутри `Gallery` допустим только как лёгкий системный feedback. Контент не управляет его параметрами.
- Стрелки, лента превью и контекстная карточка лайтбокса появляются через `120ms` после завершения анимации открытия media: opacity `0 → 1` за `400ms`. До этого они неинтерактивны, pointer/focus не обходят задержку. При листании задержка не повторяется; reduced motion сохраняет задержку, но убирает fade.
- Все `openable` image/video из нескольких `<Gallery>` внутри одной версии кейса объединяются в одну упорядоченную fullscreen-галерею. Full- и short-версии используют разные scope; `openable={false}` не входит в навигацию и превью.
- Desktop lightbox поддерживает нециклическую навигацию полноэкранными боковыми кнопками шириной 160px, клавиатурой ArrowLeft назад и ArrowRight вперёд, а также кликабельными превью с cursor pointer. Клавиатурная навигация не показывает уже скрытый интерфейс. После начального появления hit area стрелок и превью остаются активными при визуальном фейде: неподвижный курсор в такой зоне продолжает скрывать крестик, клик по невидимой стрелке перелистывает, а клик по невидимому превью открывает соответствующее media. Подавление крестика снимается только после фактического выхода курсора из зоны или закрытия лайтбокса. Wheel, trackpad, swipe и drag не переключают media. Доступная hover-стрелка использует чёрный фон `--color-black` и белую иконку `--color-white`. На краях сохраняется disabled-визуал без навигации: фон `--color-gray-150`, светлая стрелка `--color-gray-400`. Боковые зоны показывают короткий opacity-fade серого градиента, а click-feedback доступной стрелки сохраняет scale `1.12` и пружинный возврат.
- Плавающий крестик остаётся верхним UI-слоем, но скрывается над обеими полноэкранными зонами навигации, контекстной карточкой и всем занятым диапазоном ленты от первого до последнего preview, включая gap. Реальные thumbnail-кнопки и внутренние gap объединены в отдельный semantic flex-wrapper; крайние spacer-зоны остаются вне него. Активные hover-зоны учитываются как Set идентификаторов без `pointermove`-hit-test и geometry reads, поэтому выход из одной пересекающейся зоны не сбрасывает другую. Над крайними spacer-зонами ленты крестик остаётся видимым.
- Только свёрнутое состояние контекстной карточки compact и hug по содержимому: чёрный regular-заголовок, padding `--space-sm` / `--space-lg-compact`, pill radius. Actionable-вариант раскрывается по hover или keyboard focus до `560px` пружиной `220/22/1`, возвращает padding `--space-lg` / `--space-xl` и radius `--home-bubble-radius`, кроссфейдит заголовок в heavy и проявляет body до трёх строк и ссылочный label за `200ms`. Fixed-positioning и центрирование принадлежат внешнему wrapper, а layout-анимация размера и `overflow`-clip — внутренней semantic-ссылке, поэтому текст не выходит за карточку во время анимации. Reduced motion применяет конечное состояние сразу. Весь actionable-блок остаётся единственной семантической ссылкой; короткий caption-only вариант остаётся compact и не раскрывается.
- Enter/Space сохраняют возврат focus к source при обычном закрытии, но обработка ArrowLeft/ArrowRight отключает возврат к исходному media, поскольку активный элемент изменился; последующая Tab-навигация может снова включить доступный возврат.
- На mobile после первоначального появления лента превью всегда видима, поддерживает native горизонтальный momentum-scroll и mandatory center snap. Во время прокрутки media автоматически меняется на ближайшее к центру превью с `requestAnimationFrame`-ограничением частоты; финальный snapped item подтверждается после остановки scroll (`140ms` debounce). Tap по превью также выбирает media. Программное центрирование всегда занимает `200ms` независимо от расстояния; раскрытие active slot и изменение крайних spacer используют те же `200ms`. Новый переход начинает движение с фактического scrollLeft; snap возвращается после завершения движения и раскрытия. Соседние слоты сохраняют gap `--space-sm` (8px). Fullscreen media на mobile во всех фазах сохраняет фактический computed radius исходного media в кейсе.
- Горизонтальный swipe по mobile lightbox переключает media нециклически при преимущественно горизонтальном смещении не меньше `48px`; последующий synthetic click подавляется, чтобы жест не закрывал lightbox. Swipe внутри ленты остаётся её нативной прокруткой.
- Выбор media, пояснение и конечная геометрия меняются сразу, без ожидания загрузки. Shell остаётся смонтированным на всю сессию; в open-фазе геометрия задаётся напрямую в том же React commit. Переключение не использует opacity, crossfade, blur, scale, overlap, resize или повторную open-анимацию. Геометрическая анимация сохраняется только для открытия и закрытия lightbox.
- Low-resolution DOM-изображения сохраняются на время открытой галереи. Полные слои сохраняются для активного media и его непосредственных соседей. Каждый слой становится видимым только после decode своего отображаемого DOM-элемента; готовый full подменяет low без fade. Если выбранное изображение ещё не готово, старое сразу исчезает, а область остаётся пустой — без надписей загрузки, skeleton, плейсхолдеров и сообщений ошибки. Поздняя загрузка не меняет выбранный индекс. Видео становится видимым после готовности кадра.
- В лайтбоксе кейса над лентой размещается контекстная карточка: свёрнутое состояние hug по заголовку, раскрытое — шириной 560px с адаптацией к mobile, белым фоном 92%, backdrop blur 12px и основным текстом до трёх строк. Для полного кейса берутся ближайший предыдущий заголовок и первый непустой абзац этого раздела; до первого заголовка используются название кейса и первый абзац статьи. Если используется этот fallback на название кейса, активация после закрытия лайтбокса плавно прокручивает страницу к `top: 0` и не назначает anchor абзацу. При реальном предыдущем заголовке, включая «Интерактивное содержание», сохраняется переход к element target с отступом 25% viewport. `caption` не заменяет текстовое превью в полном кейсе. Все медиа одного `Gallery` показывают одинаковые заголовок и абзац. В полном кейсе вся карточка является одной ссылкой «Показать в кейсе»: hover всей карточки анимирует только подпись ссылки по стандартному стилю проекта, а активация сначала завершает закрытие и затем прокручивает к назначению контекста. В коротком кейсе карточка показывается только при наличии caption активного media и содержит только caption как компактный неинтерактивный заголовок. На About пояснения нет. Взаимодействие с карточкой не закрывает overlay и не переключает media свайпом. Карточка доступна также для единственного media.
- Mobile image поддерживает pinch zoom `1x–4x` вокруг центра жеста и double tap toggle `1x/2x` вокруг точки касания. Zoom сбрасывается при смене media и закрытии; при масштабе выше `1x` одно-пальцевый swipe галереи отключён. Desktop interaction не меняется.
- Под лентой сохранена закомментированная декларация белого градиента; сейчас белая тонировка не отображается. Прогрессивный блюр использует три статичных слоя `0 / 8 / 16px`, сохраняет прежние позиции оставшихся масок и занимает область на 60px выше базовой нижней области интерфейса. Прозрачность масок плавно меняется вместе с элементами управления за 400ms, при reduced motion — сразу.
- Превью используют `src` media (не `fullSrc`): неактивное превью имеет квадратный горизонтальный crop и opacity 50%, а активное раскрывается до полного соотношения сторон без масштабирования asset. Внешний slot активного превью расширяется вместе с crop, поэтому соседние элементы сохраняют gap `--space-sm` (8px) и не перекрываются.

Пример:
```mdx
<Gallery>
  <Media kind="image" src="/media/shot-1.png" />
  <Media kind="image" src="/media/shot-2.png" />
  <Media kind="video" src="/media/flow.mp4" />
</Gallery>
```

### 2.1) `shortSummary.media`

`shortSummary.media` описывается во frontmatter кейса, а не в MDX body.
По структуре это тот же `MediaPlaceholder[]`, что используется для `<Media />`.

Правила:
- media короткой версии рендерится после текста shortSummary через системную gallery/lightbox-логику;
- fullscreen, caption, intrinsic dimensions и загрузочное состояние наследуют поведение `MediaPlaceholder` и `GalleryLightbox`;
- assets должны оставаться внутри media-папки своего кейса (`public/media/cases/{slug}/...`);
- отдельная подпапка для short-assets не обязательна;
- имена файлов должны быть уникальными относительно основных media кейса, например `short-before.png` / `short-after.png`.

Пример:

### 4) `PortfolioMotionDemo`

Специализированная неинтерактивная motion-демонстрация для кейса `portfoliocase`.

Поведение:
- не принимает props;
- последовательно показывает одно переключение top card `to-profile -> to-home`, переключение short mode и единственный кейс `Портфолио как продукт`;
- top card и short mode автоматически воспроизводят актуальную production-хореографию смены состояния, как после пользовательского нажатия, но без интерактивного control; обе смены состояния начинаются после задержки `280ms`, а во всех состояниях top card его иконки постоянно проигрывают production hover-cycle `620ms` с исходными отрицательными задержками;
- top card сохраняет desktop-ширину `--home-top-card-width` на всех viewport; единственный кейс сохраняет естественные production-пропорции bubble по своему текстовому содержимому, целиком масштабируется в `1.2x` и центрируется внутри сцены, поэтому пропорционально увеличиваются текст, стикер, скругление, тени и деформация пузыря;
- стеклянный пузырь закреплён за единственным кейсом; после проявления кейса он появляется с задержкой `140ms`, одновременно меняя opacity за `280ms` и scale `0.1 -> 1` с пружинным хвостом `stiffness: 220`, `damping: 14`, `mass: 1`, после чего запускается frame-cycle связанных декоративных стикеров;
- общий motion-ритм замедлен в `1.2x`: outgoing проходит `0 -> 120px` за `720ms`, а новая сцена достигает верхней точки на границе lifecycle `1440ms`;
- outgoing использует `cubic-bezier(0.7, 0, 0.84, 0)`; opacity остаётся `1`, а blur — `0px`, пока фактически не пройдены первые `60px`, и только на оставшейся половине пути меняются до `0` и `18px`;
- incoming начинает полёт при outgoing opacity `0.5` (примерно `683ms`) и проходит `120px -> 0` по зеркальной `cubic-bezier(0.16, 1, 0.3, 1)`; к моменту прохождения первых `60px` подъёма (примерно `760ms`) он уже полностью проявлен и очищен от blur;
- точка равной видимости двух сцен составляет примерно `24.4% / 24.4%`, поэтому ограничение пересечения не выше `30% / 30%` соблюдается; вертикальное движение не имеет статичной паузы;
- каждая сцена проходит rotation насквозь через `0deg`: пришедшая из `-15deg` уходит в `15deg`, а пришедшая из `15deg` — в `-15deg`; стартовое направление чередуется между сценами и через стык цикла;
- внутренняя production-анимация сцены запускается один раз точно при достижении входящей opacity порога `0.8`: после своей задержки запускается единственный top-card switch `to-profile -> to-home`, short-mode switch или появление пузыря со стикерами;
- единственный кейс проходит подъём и падение как одну непрерывную траекторию без отдельного exit-delay и зависания в верхней точке; opacity и blur меняются только после первых `60px` соответствующего участка пути;
- short-mode control масштабируется целиком через `transform: scale(2)`, его внутренняя production-геометрия не меняется;
- белый viewport не имеет border/outline и использует высоту `calc(--layout-preview-size - --space-4xl - --space-2xl)` (`412px`); центр сцены смещён вверх на `--space-4xl + --space-xl` (`68.8px`), поэтому верхняя точка находится на линии верхней трети (`≈137.2px` при целевых `≈137.3px`), а снизу сохраняется полный запас под падение `120px`, поворот `±15deg`, blur-хвост и внешний масштаб кейса `1.2x` без обрезания;
- каждая завершившая exit-сцена вызывает `safeToRemove` через `720ms`, поэтому следующий цикл получает новый экземпляр с начальными motion values; при паузе таймер останавливается, а после возврата presence-сессия пересоздаётся со следующей дискретной сценой без накопленных exit-слоёв;
- компонент не содержит ссылок, кнопок, hover/focus/click-обработчиков и полностью исключён из pointer interaction;
- при `prefers-reduced-motion: reduce` отображается статичный единственный кейс без цикла;
- renderer может использовать этот же компонент в типизированном case-specific `shortAfterContent`-slot после всего текста и `shortSummary.media`; slot не входит во frontmatter/MDX-контракт, а full- и short-экземпляры компонента монтируются взаимоисключающе;
- цикл работает только при пересечении области viewport с `rootMargin: "100px 0px"` и видимом документе; при выходе из области или скрытии вкладки таймеры и motion-слои останавливаются с сохранением текущей дискретной сцены, а при возврате воспроизведение продолжается со следующей сцены без восстановления промежуточного прогресса перехода;

Пример:
```mdx
<PortfolioMotionDemo />
```
